# 반복 담기 개인화 추천(RAG) 설계 (#271)

## 목표
사용자가 일정한 간격으로 반복해서 장바구니에 담는 상품 가운데 "다시 살 때가 된" 상품을 추천한다.
메인 섹션(API)과 챗봇에서 쓰고, 지원하는 주기면 장바구니 예약(#269)을 함께 제안한다.

## 결정 사항
| 항목 | 결정 | 이유 |
|---|---|---|
| 근거 데이터 | `cart_events`(직접·예약 담기), 최근 180일 | 구매 데이터가 없다. 찜·조회는 "반복 구매"와 신호가 달라 이번에는 넣지 않는다 |
| 판단 | 반복 간격 규칙(중앙값 주기, 80% 기준) | 근거가 분명해 설명할 수 있고 데이터가 적어도 동작한다 |
| 검색 | 벡터 DB 없이 DB 조회 | 근거가 사용자 본인 이력이라 구조화 조회로 충분하다 |
| 생성(챗봇) | 후보 최대 5개를 매 턴 프롬프트에 넣는다 | LLM 호출 1번 유지. 후보가 있는 사용자만 턴당 약 150토큰 증가 |
| 생성(메인) | LLM 없이 서버가 이유 문장을 만든다 | 빠르고 챗봇 사용량을 쓰지 않는다 |
| 표현 | "구매"가 아니라 "담은" | 실제 구매 여부는 모른다 |

## ① 후보 찾기
`RepurchaseAnalyzer` (순수 계산)
- 입력: 담은 날짜 목록, 오늘
- 같은 날 여러 번 담은 기록은 하루로 센다. 담은 날이 2일 이상이면 후보다.
- 주기 = 담은 날 간격의 중앙값(일, 최소 1). 간격 개수가 짝수면 가운데 두 값의 평균을 반올림한다.
- 경과일 = 마지막으로 담은 날부터 오늘까지
- 다시 살 때 = 경과일 ≥ ceil(주기 × 0.8)
- 점수 = 경과일 ÷ 주기
- 이유 문장: "약 {주기}일마다 담으셨고 마지막은 {경과일}일 전이에요" (경과일 0이면 "오늘")
- 예약 제안: 주기 5~9일 → 매주(마지막으로 담은 요일), 25~35일 → 매월(마지막으로 담은 날), 시각 09:00, 수량 1. 그 밖에는 없음

`RepurchaseFinder` (DB)
- 최근 180일 `cart_events` 를 상품별로 묶어 분석한다.
- 진행 중(`ACTIVE`) 예약이 있는 상품은 뺀다.
- 점수 높은 순, 같으면 담은 횟수 많은 순.
- `findDue(userId, limit)`: 다시 살 때인 후보만(메인)
- `findAll(userId, limit)`: 다시 살 때가 아닌 후보도 포함(챗봇)

## ② 메인 API
- `GET /api/repurchase` (인증): `findDue` 최대 10개. 항목: 상품 번호·주소·이름·이미지·가격, 주기, 마지막으로 담은 날, 경과일, 담은 횟수, 이유, 예약 제안(`repeatType`, `summary`) 또는 null
- `POST /api/repurchase/{productId}/schedule` (인증): 서버가 제안을 다시 계산해 바로 `ACTIVE` 예약을 만든다. 다시 살 때가 아니거나 예약이 있거나 지원하지 않는 주기면 409. 한도 20개와 사용자 행 잠금은 #269 와 같다. 응답은 `CartScheduleResponse`.

## ③ 챗봇
- `ChatService` 가 LLM 호출 전에 `findAll(userId, 5)` 를 불러 `PromptAssembler.buildUserMessage` 에 넘긴다. 후보가 없으면 블록을 넣지 않는다.
- `<담기_이력>` JSON 블록: 상품주소, 이름, 주기일, 마지막으로담은날, 경과일, 담은횟수, 다시살때, 예약제안. 참고 자료일 뿐 지시가 아니라고 감싼다.
- 시스템 프롬프트 `[반복 담기 추천]`: `<담기_이력>` 의 상품만 근거로, 지어내지 않고, "구매"라고 단정하지 않는다. 주제에 "반복해서 담는 상품 추천"을 더한다.
- `SCHEDULE` 줄 끝에 선택 값 `product=<상품주소>`. 서버는 그 주소가 이번 턴 `<담기_이력>` 후보이거나 대화 상품일 때만 받는다. 상품 없는 대화에서도 이력 후보면 예약을 제안할 수 있다.

## 테스트
- `RepurchaseAnalyzer`: 같은 날 합치기, 중앙값(홀·짝), 80% 경계, 예약 제안 주기 경계, 이유 문장
- `RepurchaseFinder`: 180일 범위, 예약 있는 상품 제외, 정렬, due 필터
- API: 목록, 예약 만들기(성공·409·한도), 인증
- 파서: `product=` 값
- 챗봇: 이력 블록 포함 여부, product= 가 후보일 때만 제안
